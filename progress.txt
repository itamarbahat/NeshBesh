## PRD.md — Engine, Special Rolls, Bear-off & Performance (2026-05-04)

### Open questions resolved during clarification
- **5/1 (1/5)** is a single trigger: roll one die, play 4 moves of that rolled value.
  Bar-entry and bear-off each consume one of the four moves regardless of pip distance.
- **Blocked-double-on-Bar** → full re-roll; 3 consecutive blocked doubles → Table Flip
  (reuses existing 3-doubles-in-a-row rule and `useTableFlipAnimation`).
- **6/5 Nesh Strike** always grants 2 free moves. When on the Bar, the FIRST free
  move must land in opponent's home (= bar entry); the SECOND is unrestricted.
  The "last piece on Bar exception" is REMOVED.
- **Bear-off "must advance higher"** uses standard semantics — "higher" = farther
  from the player's exit, computed per side (not raw array index).
- **Performance** focuses on `calculatePossibleMoves` path search (Click 1 hot path).

### Implementation notes (2026-05-05)
- **US-001 (bear-off rule)** — added `isLegalBearOff(board, sign, fromSlot,
  dieValue, excludedSlot?)` to engine. The path-search `addFinal` helper now
  gates every off-board landing by this rule. `excludedSlot` defaults to the
  original `from` so the moving piece does not block its own overshoot.
  "Farther from exit" is per-side: White → lower index in [19..fromSlot-1],
  Black → higher index in [fromSlot+1..6].
- **US-002 (`isBarEntryBlocked`)** — added to engine. Pure `(board, sign,
  dieValue) => boolean`. Wired into the rollDice double path.
- **US-003 (`getFreeMoveFinals` flag)** — added optional `opponentHomeOnly`
  param. White → restricts to slots 1..6, Black → 19..24. Existing call sites
  unchanged (default false).
- **US-004 / US-005 / US-006 / US-007 (5:1 four-move mode)** — added
  `is51FourMove: boolean` to the store interface and `resetTurnState`. The
  bar branch now sets `availableDice: [d, d, d, d]` and routes through
  `enterMovingOrSkip`. Engine's existing `getDiceAfterMove` already handles
  bar-entry (slice one die for an exact pip match) and bear-off (smallest
  eligible die >= distance) so consumption math needed no engine change.
- **US-008 / US-009 (blocked double on bar)** — added `blockedDoubleStreak`
  to the store. rollDice doubles path detects `hasBarPieces && isBarEntryBlocked`,
  increments the streak, sets `phase=WAITING_ROLL` with a Hebrew "blocked"
  message, and schedules `setTimeout(get().rollDice, 1200)` guarded by a
  dice-snapshot check (so a manual mid-cooldown roll does not fire a duplicate
  auto-roll). `streak === 3` → `phase=TABLE_FLIP`. Streak resets on any
  non-blocked roll, every successful double, and `resetTurnState`.
- **US-010 (6:5 free-move bar restriction)** — final shape:
  `neshStrikeStartedOnBar` is latched true at the 6:5 trigger when the player
  has bar pieces. While the latch is true, BOTH free-move destinations are
  restricted to opponent's home (`getFreeMoveFinals(board, sign, true)`); the
  FIRST move's source is forced to be the bar checker, the SECOND move's
  source is any of the player's checkers. When the latch is false (player
  did not start on Bar), both moves are unrestricted. rollDice's 6:5 trigger
  pre-checks if opponent's home is fully blocked → forfeits both moves and
  SKIPs the turn. Reset by `resetTurnState`.
- **US-011 (last-piece exception removed)** — confirmed no code path ever
  reduced `neshStrikeFreeMovesLeft` from 2 to 1; CLAUDE.md §2 6:5 bullet
  rewritten to describe the new bar-first/then-free behavior.
- **US-012 (5:1 dice indicator)** — no code change required. DicePanel
  already renders the `isSpecialDouble` case (4 dice of value `availableDice[0]`
  with greyed-out used slots) and the bar branch now feeds it the same
  `[d, d, d, d]` shape.
- **US-013 (blocked-double feedback)** — message string drives the existing
  toast/overlay path. No new animation hook; the table-flip case reuses
  `useTableFlipAnimation` via the existing `phase === 'TABLE_FLIP'` watcher
  in App.tsx.
- **US-015 (memoize path search)** — added a turn-scoped `Map<string,
  MoveResult>` cache inside `engine/index.ts`. Cache key = `board.join(',')|
  from|sign|dice.join(',')|backward|bearOff`. `resetMoveCache()` is exported
  and called from `endTurnImpl`, after every successful `applyMove` in
  `handlePointPress`, and after every Nesh Strike free move.
- **US-016 (selector narrowing)** — partially landed: `SpecialRollOverlay`
  now subscribes via narrowed `useGameStore((s) => s.field)` selectors instead
  of the full state. `ThrowingDiceOverlay`, `OpponentHeaderChip`,
  `RemoteBottomBar` still subscribe to the full state — flagged for a
  follow-up pass.
- **US-014 (perf instrumentation)** — deferred. The memoization in US-015
  should land the bulk of the win on its own; profiling can confirm post-merge.
- **Multiplayer sync** — new fields `is51FourMove` and `blockedDoubleStreak`
  are host-only logic and do not drive guest rendering, so the Firebase
  `gameState` payload in App.tsx was NOT extended. If a future story relies
  on the guest knowing either, add them to both the host `syncGameState`
  payload and the guest `subscribeToGameState` hydrator.
- **CLAUDE.md** — §2 updated: new "Blocked Double on Bar" turn-flow bullet,

### PRD-dice-polish.md — implementation notes (2026-05-05)
- New module `src/animations/diceConstants.ts` owns all dice timing/scale
  magic numbers (`TRAY_DIE_SCALE=1.6`, `BOARD_DIE_SCALE=1.0`,
  `LANDING_POP_SCALE=1.25`, `LANDING_POP_MS=180`, `ROLL_DURATION_MIN_MS=1000`,
  `ROLL_DURATION_MAX_MS=4000`) plus `getRollDurationMs` and
  `pickLandingPoint`/`pickPairLandingPoints`.
- `getOccupancyRects(board, boardWidth, boardHeight)` lives in
  `boardConstants.ts` and returns rects in board-local coords (origin at the
  border-frame top-left). `BOARD_FROZEN` constants were NOT modified.
- `ThrowingDiceOverlay` measures itself via `onLayout` so the dice land
  inside the framed playing surface regardless of bear-off row presence.
  Each roll calls `getRollDurationMs()` once and threads the value to both
  the flight `Animated.timing` and `audio.playShakeFor(...)` so the shake
  SFX matches the flight window. On landing it triggers `audio.playDiceLand()`
  plus a per-die scale pop sequence (`BOARD_DIE_SCALE * LANDING_POP_SCALE`
  over 80ms then settle).
- `DicePanel` multiplies the incoming `dieSize` by `TRAY_DIE_SCALE` for the
  three tray "ready to throw" rendering paths only. Result/used dice on the
  board still use unmodified `dieSize`.
- `useAudioManager` adds `playShakeFor(durationMs)`, `playDiceLand()`,
  `playCheckerClick()`. The shake handle owns module-scope generation/timer
  state so a new shake cleanly stops the previous loop. Pitch modulates
  ±8% every ~150ms via `setRateAsync(rate, false)`.
- Existing `playRollDice` and `playMovePiece` are kept as documented
  no-op transients (asset is `null`); the audible dice/check-click sounds
  are the new shake/land/click layers. Click is gated on `phase === 'MOVING'`
  and excludes `Captured`-message moves (those still route to `playEatPiece`).
- Placeholder WAVs were generated by `scripts/generate-sfx.py` (Python
  fallback for environments without Node) and committed under
  `neshbesh-app/assets/sfx/`. The TS equivalent `scripts/generate-sfx.ts`
  is checked in for future regeneration via `npm run sfx:generate`.
- US-014 aesthetic regression: `git diff` confirms zero changes to
  `Board.tsx`, `Piece.tsx`, `Slot.tsx`, or to `BOARD_FROZEN` color/ratio

## PRD.md — UI Performance, Dice Physics, Audio & Static Board (2026-05-05)

> Active PRD. Prior engine/rules PRD archived as `PRD-engine-rules.md`.
> Release window: 2026-06-10.

### Open questions resolved during clarification
- **Lag scope** — Click-1 tap-to-select is the primary symptom; cross-platform
  60 fps target; treated as a recent regression to bisect-and-fix.
- **Dice physics** — 3 s hard cap (snap to final pose if overrun); elastic
  walls; dice-on-dice collision enabled; pip-indicator region treated as a
  forbidden landing zone.
- **Audio** — staggered per-die triggers for roll / land / collision; new
  bear-off SFX; reference recording supplied by user out-of-band; placeholder
  fallback preserved until US-015 swap.
- **Static board** — applies to BOTH local hotseat and remote two-device
  modes. Board container fixed-center; chrome reflows or overlays without
  translating the board.

### Implementation notes (2026-05-05)

- **US-001 — regression diagnosis.** Click-1 lag is React render storm,
  not engine. The `5fe6a8d` engine path-search cache (`resetMoveCache` +
  `_moveCache`) is intact and effective (µs cost on cache hit). The
  visible lag is in component render: every `selectedIndex` /
  `intermediateHighlights` / `finalHighlights` update re-rendered all
  24 `<Slot>` SVG cones + ≤7 `<Piece>` per slot because none of `Slot`,
  `BarSlot`, `Piece` were `React.memo`-wrapped, and `BoardContent` in
  [App.tsx](neshbesh-app/App.tsx) destructured the full `useGameStore()`
  state — so any unrelated store mutation (dice, message, phase, score,
  doublesCount) re-rendered the whole board subtree.
- **US-002 — fix.**
  - [Piece.tsx](neshbesh-app/src/components/Piece.tsx): renamed inner
    function to `PieceImpl`, exported `Piece = React.memo(PieceImpl)`.
  - [Slot.tsx](neshbesh-app/src/components/Slot.tsx): same memo pattern
    for `Slot` and `BarSlot`; replaced inline
    `() => onPress(index)` with a `useCallback`-stabilised `handlePress`
    so the memo isn't busted by a fresh closure each render.
  - [App.tsx](neshbesh-app/App.tsx) `BoardContent`: replaced the full
    `useGameStore()` destructure with seven narrowed selectors
    (`board`, `whiteBorneOff`, `blackBorneOff`, `selectedIndex`,
    `intermediateHighlights`, `finalHighlights`, `handlePointPress`),
    so the component only re-renders on board-relevant slices.
- **US-003 — narrow subscriptions.** `ThrowingDiceOverlay`,
  `OpponentHeaderChip`, and `RemoteBottomBar` were already on narrowed
  selectors (the original PRD-engine-rules progress note was stale).
  Verified each component's selector list matches the fields it
  actually renders:
  - `ThrowingDiceOverlay`: `dice`, `phase`, `board`, `currentPlayer`
    (engine), `gameMode`, `role` (multiplayer). `board` is needed for
    `getOccupancyRects` collision-aware landing math; `currentPlayer`
    drives throw direction.
  - `OpponentHeaderChip`: `currentPlayer`, `phase`, `whiteBorneOff`,
    `blackBorneOff`, plus `opponentName` from multiplayer.
  - `RemoteBottomBar`: `currentPlayer`, `whiteBorneOff`, `blackBorneOff`,
    `phase`, `dice`, `availableDice`, `board`, `backward`, `endTurn`.
    `board` and `backward` are needed for `currentPlayerHasLegalMoves`
    which drives the conditional No-moves/End button.
- **US-004 — static board, local hotseat.**
  - [App.tsx](neshbesh-app/App.tsx) `CenteredDiceBar` (landscape):
    refactored from "single instance, conditional on currentPlayer"
    to **sided** — accepts `playerSign: 1 | -1` and renders an idle
    placeholder of equivalent reserved height when not the active
    player. The landscape `centerStage` now mounts both
    `<CenteredDiceBar playerSign={1} />` and
    `<CenteredDiceBar playerSign={-1} />` on every turn so the column's
    total content height (whiteBar + board + blackBar) is constant.
    Reserved panel height is `Math.max(56, dieSize * 1.6 + 24)` to
    cover the active DicePanel's tray scale.
    Subscriptions on `CenteredDiceBar` were also narrowed in the same
    pass.
  - `PlayerDiceBar` (portrait): subscriptions narrowed; `playerBar`
    style gained `minHeight: 96` so DicePanel content transitions
    (waiting → rolled-result → no-moves) no longer reflow the parent
    `mainContent` flex column and shift the board.
- **US-005 — static board, remote two-device.**
  - [OpponentHeaderChip.tsx](neshbesh-app/src/components/OpponentHeaderChip.tsx)
    `chip` style gained `minHeight: 50` so opponent activity
    transitions (idle ↔ Rolling… ↔ Thinking…) reserve constant
    vertical space.
  - [RemoteBottomBar.tsx](neshbesh-app/src/components/RemoteBottomBar.tsx)
    `bar` style gained `minHeight: 96` so my-turn ↔ opponent-turn
    transitions don't reflow the board.
- **US-006 — chrome reflow audit checklist.** See "Manual Test Plan
  · Static-Board Audit" below. Each row records the board's measured
  top-left in two states; the `0 px Δ` column must be 0 in every row.
  Measurement to be performed with React Native's `findNodeHandle` +
  `measureInWindow` or by overlaying a fixed reference at the screen
  center and verifying the board edge stays aligned.

- **US-007 / US-008 / US-009 / US-010 — dice physics rewrite.** The
  prior `Animated.timing` flight (linear lerp from off-screen to a
  pre-picked landing point) was replaced with a deterministic 2D rigid
  body simulator in
  [diceConstants.ts](neshbesh-app/src/animations/diceConstants.ts):
  - New constants: `PHYSICS_RESTITUTION` (0.55), `PHYSICS_FRICTION_PER_FRAME`
    (0.965), `PHYSICS_ANGULAR_FRICTION_PER_FRAME` (0.955),
    `PHYSICS_REST_VELOCITY` (0.015 px/ms), `PHYSICS_REST_ANGULAR`
    (0.0008 rad/ms), `PHYSICS_FRAME_DT_MS` (16), `ROLL_HARD_CAP_MS` (3000).
  - `ROLL_DURATION_MAX_MS` lowered from 4000 → 3000 (US-009).
  - `simulateDiceFlight(opts)` time-steps two `RigidBody` instances at
    16 ms/frame for ≤188 frames. Per frame: integrate position +
    rotation, `clampToWalls` reflects velocity at board edges
    (US-007), `clampToForbiddenRects` reflects along the shallowest
    axis when overlapping any checker stack or the bar strip (US-010),
    and `resolveDieDie` applies elastic circle-circle response with
    impulse exchanged along the contact normal (US-008). Friction
    decays velocity each step. Per-die rest detection feeds the
    staggered audio cues in US-014.
  - Returns `framesA[]`, `framesB[]`, `collisionFrames[]`,
    `bounceFramesA[]`, `bounceFramesB[]`, `restFrameA`, `restFrameB`.
    If both dice settle before the cap, remaining frames freeze at the
    rest pose so the renderer can drive a fixed-length animation
    without branching. If motion never converges within
    `ROLL_HARD_CAP_MS`, the last frame holds the final pose and the
    renderer hard-snaps to it (US-009 acceptance).
  - [ThrowingDiceOverlay.tsx](neshbesh-app/src/components/ThrowingDiceOverlay.tsx):
    `animateThrow` now runs `simulateDiceFlight` before any rendering,
    then drives a JS-thread `requestAnimationFrame` tick that pumps
    sampled poses into `Animated.Value` instances via `setValue`. Tick
    handle stored in `tickHandleRef` so a fresh roll cancels the
    previous simulation cleanly (`cancelTick`). The rotation
    interpolation was rewritten from "tumble revolutions → degrees"
    to "radians → degrees" (`inputRange: [-π, π], outputRange:
    ['-180deg', '180deg'], extrapolate: 'extend'`) to render physics
    output correctly. `Easing` import retained for the in-flight scale
    timing, which still uses the native driver. `pickPairLandingPoints`
    is no longer called from this file but remains exported for any
    future static-target use.
  - Forbidden rects fed to the simulator: every occupied checker stack
    (existing `getOccupancyRects` output) plus a permanent bar strip
    rect of width `BOARD_FROZEN.BAR_WIDTH_RATIO × innerW` and full
    inner-board height. Dice now physically bounce off the bar like a
    real backgammon set's wooden ridge (US-010).
- **US-011 — audio API per-die surface.**
  [useAudioManager.ts](neshbesh-app/src/audio/useAudioManager.ts):
  - Added events `dieRoll`, `dieLand`, `dieCollision`, `bearOff` to
    `SoundEvent` and `SOUND_ASSETS` (all `null` until US-015).
  - `AudioManager` interface gained `playDieRoll(idx, durationMs)`,
    `playDieLand(idx)`, `playDieCollision()`, `playBearOff()`.
  - Each method uses the existing `playSound` no-op-on-null path so a
    missing asset silently does nothing — matches the
    `playRollDice` / `playMovePiece` pattern from PRD-dice-polish.
  - Module-scope `collisionEarliestMs` rate-limits collision SFX to
    one trigger per `COLLISION_MIN_GAP_MS` (90 ms). The simulator also
    has a 6-frame cooldown so the audio limiter is the second line of
    defence.
- **US-012 — collision SFX wiring.** The simulator records every
  discrete contact event in `collisionFrames`; the renderer's tick
  loop walks a `collisionCursor` and fires `audio.playDieCollision()`
  as `frameIdx` crosses each entry. No collision SFX fires on
  single-die phases (impossible — two bodies always simulated) or at
  rest (`resolveDieDie` returns false on no overlap).
- **US-013 — bear-off SFX wiring.** Side effect on the existing
  `useEffect([phase, message, dice])` in
  [App.tsx](neshbesh-app/App.tsx): when `message === 'Borne off!'`
  and the message changed since last tick, fire `audio.playBearOff()`.
  This single signal covers regular bear-off, doubles bear-off, and
  the 5:1 four-move special (each emits the same message string per
  successful bear-off in `handlePointPress`).
- **US-014 — staggered per-die roll/land triggers.**
  - At throw start, `audio.playDieRoll(0, flightMs)` fires
    immediately and `playDieRoll(1, …)` fires after a 30–120 ms
    randomized stagger so the two dice never sample-lock.
  - Per-die land cues fire when the playback `frameIdx` crosses each
    die's `restFrameA` / `restFrameB`, which differ naturally because
    the simulator detects each body's rest state independently.
  - Legacy `playShakeFor` and `playDiceLand` now early-return when
    their per-die counterparts have non-null assets, so once US-015
    lands real `dieRoll` / `dieLand` files, the legacy layer falls
    silent automatically with no further wiring needed.
- **Typecheck status.** NOT verified locally — `node`, `npx`, and
  `tsc` are not on PATH in this Windows dev environment (verified by
  `Get-Command` and bash `which`). User should run
  `npx tsc --noEmit` from `neshbesh-app/` to verify.

- **US-015 — reference recordings (Path A).** User chose to wire the
  raw MP3 references in directly and play them at low volume rather
  than synthesize new placeholders.
  - Files copied:
    `.claude/sounds/dice shrowing sound.mp3`
      → `neshbesh-app/assets/sfx/dice-throw.mp3`
    `.claude/sounds/moving sound.mp3`
      → `neshbesh-app/assets/sfx/checker-move.mp3`
  - `useAudioManager.ts` `SOUND_ASSETS` rewired:
    `dieRoll` → `dice-throw.mp3` (vol 0.25 die0 / 0.18 die1),
    `checkerClick` → `checker-move.mp3` (vol 0.30),
    `bearOff` → `bear-off.wav` (new procedural bell — vol 0.55),
    `dieCollision` → `die-collision.wav` (new procedural tick —
      vol 0.40),
    `dieLand`, `diceShake`, `diceLand`, `movePiece` → `null` so no

  - `scripts/generate-sfx.py` extended with `make_bear_off_chime()`

  - **Multi-throw bleed handling.** The user's `dice-throw.mp3` is
