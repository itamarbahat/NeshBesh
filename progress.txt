# Progress Log

## Learnings

### PRD-multiplayer.md — implementation notes (2026-05-04)
- `expo-linking` added to `package.json` at `~8.0.8` (Expo SDK 54). User must run
  `npm install` from `neshbesh-app/` before the dev server starts.
- Deep link parsing lives in `App.tsx` (cold + warm start), not `LobbyScreen.tsx`,
  because cold-start URLs must be captured before screen routing decisions.
- `pendingJoinCode` was added to `useMultiplayerStore` so the App-level URL
  listener can stash a code that the lobby consumes (auto-join if `playerName`
  set; prefill manual input otherwise).
- QR scan code path was preserved verbatim — only the entry point was demoted
  behind a `אפשרויות הצטרפות נוספות ▾` disclosure on the IDLE lobby and a
  `אפשרויות נוספות ▾` disclosure on the HOSTING screen.
- `gameMode` defaults to `'local'`. `startLocalGame()` keeps it `'local'`;
  `hostRoom()` and `joinExistingRoom()` flip it to `'remote'`. `resetToLobby()`
  resets to `'local'`. The remote layout branch in `App.tsx` short-circuits both
  portrait and landscape paths so local hotseat rendering is byte-equivalent
  for the `gameMode === 'local'` path.
- Typecheck status: NOT verified locally — `node`/`npm`/`tsc` are not on PATH
  in this dev environment. User should run `npx tsc --noEmit` from
  `neshbesh-app/` to verify.
